- Multi-factor decision logic (price, urgency, battery state)
- Physical constraint enforcement (charge/discharge limits)

**Critical Limitations:**
1. **Battery underutilization (0.0%)**: Despite 168 MWh capacity, battery is never discharged to serve backlog
2. **$2.56M gap to theoretical optimum**: Suggests missing arbitrage opportunities

4. **Weak backlog discharge logic**: Only discharges when `urgency_factor > 0.5` (backlog age > 18h), missing earlier economic opportunities

## Recommended Improvement: Opportunistic Battery Discharge for Price Arbitrage

### The Problem
The policy only discharges battery defensively (when backlog is urgent). It misses **proactive arbitrage**: discharge battery during high-price periods to offset firm load, even without immediate backlog deadline pressure.

### Implementation

**Add battery arbitrage logic before backlog discharge decisions:**

```python
def take_action(self, ...):
    # ... existing price history and urgency calculations ...
    
    # NEW: Opportunistic battery arbitrage (insert after urgency_factor calculation)
    # Discharge battery to reduce expensive load when conditions align
    if (current_price > self.price_percentile_75 * 1.15 and  # High price regime
        battery_soc_ratio > 0.35 and                          # Sufficient charge
        oldest_backlog_age_h < 18.0):                         # No extreme urgency yet
        
        # Calculate expected price recovery window (next 6 hours)
        # Discharge aggressively if price is >25% above 75th percentile
        discharge_capacity = min(battery_power_mw, battery_soc_mwh / 1.0)
        arbitrage_discharge = min(discharge_capacity, 60.0)  # Up from 30-80 scattered logic
        battery_mw = -arbitrage_discharge
        flex_serve_mw = arriving_flex_mw * 0.3  # Reduce flex serving to prioritize firm load offset
        
        return (flex_serve_mw, battery_mw)
    
    # ... rest of existing logic ...
```

### Specific Parameter Changes

| Parameter | Old Value | New Value | Rationale |
|-----------|-----------|-----------|-----------|
| Battery discharge trigger | `urgency_factor > 0.5` (18h+) | `price_percentile_75 * 1.15` (high price) | Capture price spikes earlier |
| Min SOC for discharge | Implicit (0.5) | **0.35** | Allow deeper cycling while maintaining emergency margin |
| Arbitrage discharge rate | 30-80 MW (scattered) | **60 MW** (consistent) | Maximize peak-hour firm load offset |
| Price threshold premium | None | **+15%** above 75th percentile | Avoid discharging on marginal price increases |
| Backlog age cutoff | None | **< 18 hours** | Preserve charge for deadline-critical periods |

### Why This Works

1. **Targets the 0% battery utilization problem** directly—creates explicit conditions to discharge
2. **Reduces peak price exposure** by serving firm load with battery during expensive periods instead of buying grid power
3. **Maintains backlog safety** with age-based cutoff (won't drain battery when deadlines near)
4. **Low implementation risk**—uses existing price percentile tracking and constraint logic

This is the highest-leverage single change: the battery is an expensive asset that's currently unused while you're paying peak prices. This improvement unlocks its economic value.
