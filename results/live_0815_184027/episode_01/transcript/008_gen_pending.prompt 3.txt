1. Deferred compute must be served within 24 hours (the environment

3. flex_serve_mw >= 0; serving beyond arrivals draws down the backlog

# Novel Dispatch Architecture: Dual-Horizon Constraint-Based Optimization

## Analysis of Current Implementation

### Strengths
- ✓ Temporal pattern learning (hour-of-day statistics)
- ✓ Multi-objective awareness (urgency, peaks, battery state)
- ✓ Rolling 24h horizon
- ✓ Conservative deadline handling (exponential urgency)

### Critical Limitations
1. **Greedy Myopia**: Flex and battery decisions are decoupled; no joint optimization across states
2. **Weak Lookahead**: Binary opportunity detection (cheap/expensive) lacks probabilistic reasoning
3. **Reactive Urgency**: Exponential urgency doesn't account for remaining capacity or future opportunity windows
4. **Static Targets**: Fixed SOC targets don't adapt to load/price volatility ahead
5. **No Constraint Propagation**: Decisions don't enforce feasibility across the horizon
6. **Stagnation Root Cause**: Performance plateau suggests the heuristic is hitting a local attractor; needs algorithmic reset

**Gap to optimum: $2.88M (20% inefficiency)** — this is addressable.

---

## Proposed Architecture: Dual-Horizon Constraint Programming with Lagrangian Relaxation

### Core Idea
Replace greedy heuristics with a **lightweight constraint satisfaction + price-driven scheduling** that:
1. Commits flex/battery schedules only when they satisfy hard constraints (deadline, SOC bounds)
2. Uses **cost-to-deadline ratios** to decide serve timing across the horizon
3. **Pre-computes feasible windows** for backlog clearing before committing dispatch
4. **Dynamic battery reserve** based on load forecast volatility

    def _compute_cost_to_deadline_ratio(self,

                                        oldest_backlog_age_h: float,

        """
        NEW: Core decision logic.
        For each future hour, compute the cost of serving backlog then vs. later.
        
        Returns dict with keys:
        - 'cost_to_serve': array of (price * load_pressure) for each hour
        - 'feasible_windows': list of (start_h, end_h, total_capacity_mwh)

    def _identify_feasible_windows(self,

                                   backlog_mwh: float,

        NEW: Constraint propagation.
        Find time windows where we can serve backlog without violating:
        - Total load <= 350 MW
        - Battery SOC stays in [min_reserve, max_soc]
        - Deadline not violated
        
        Returns list of (start_hour, end_hour, available_capacity_mwh)

            else:

                    windows.append((current_window_start, h - 1, cumulative_capacity))
                    current_window_start = None
                    cumulative_capacity = 0.0

            windows.append((current_window_start, 23, cumulative_capacity))

        must_serve_rate = metrics['must_serve_mw']
        cost_to_serve = metrics['cost_to_serve']
        feasible_windows = metrics['feasible_windows']

            else:

            else:
                return arriving_flex_mw  # Wait for better time

        if deadline_pressure >= 0.40:
            price_p50 = np.percentile(cost_to_serve[:12], 50)
            if cost_to_serve[0] <= price_p50 * 0.85:  # Current price is good
                serve_now = min(self.flex_capacity_mw - arriving_flex_mw,
                               0.25 * backlog_mwh / max(24.0 - oldest_backlog_age_h, 1.0))
                return min(self.flex_capacity_mw, arriving_flex_mw + serve_now)
            return arriving_flex_mw

        price_p25 = np.percentile(cost_to_serve[:24], 25)
        load_p25 = np.percentile(load_forecast[:24], 25)

            return min(self.flex_capacity_mw, arriving_flex_mw + serve_now)
        
        return arriving_flex_mw
